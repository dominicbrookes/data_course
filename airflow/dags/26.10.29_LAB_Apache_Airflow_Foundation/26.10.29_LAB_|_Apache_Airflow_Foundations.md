Q. 3 — Draw the Airflow Component Flow

Draw a simple flow using: DAG file, Scheduler, Metadata database, Executor, Task, Webserver / UI

Show how the parts work together at a high level.

========================================================================
ANSWER Q3
========================================================================

A["DAG File"] --> B["Scheduler"]
# The DAG file is a .py file that defines the workflow: the tasks,
# ...the order they run in, and the schedule.

B --> C["Metadata Database"]
# The scheduler (a part of airflow) reads the DAG file, creates DAG runs, and records
# ...them and their task states in the metadata database.

B --> D["Executor"]
# When a task's dependencies are met (the prior tasks in the DAG file), the scheduler 
# ...hands it to the executor.

D --> E["Task"]
# The executor launches the task using the configured execution method.

E --> C
# The task's result (e.g. success / failed) is saved back to the
# ...metadata database.

C --> F["Webserver / UI"]
# The UI reads from the metadata database to show DAG runs and
# ...task states.

"""
The scheduler and the executor work as a pair in Airflow: the scheduler decides what runs, and the executor launches it. The scheduler keeps checking each DAG's schedule and task dependencies, and once a task's upstream tasks have all succeeded, it marks that task as ready and hands it over. The executor then launches the ready task using the configured execution method. That might be LocalExecutor, which runs tasks on the same machine as in my `airflow standalone` setup, or something like Celery or Kubernetes, which spread tasks across several machines.

Q. 18 — Find the Component Problem

The Airflow UI opens, but no scheduled work is being created.

Which component would you check first, and why?

========================================================================
ANSWER Q18
========================================================================

I would check the scheduler first. The scheduler is the component that
creates scheduled DAG runs and decides which tasks are ready to run.
The UI is a separate component, so it can open and show the DAGs
normally even when the scheduler has stopped or crashed. If no
scheduled work is being created, the most likely cause is that the
scheduler isn't running.

How to check:
- In the UI: go to Home and look at the Health section. The Scheduler
  should show as healthy.
- In the terminal: run  airflow jobs check --job-type SchedulerJob
  It should say it found an alive job.
